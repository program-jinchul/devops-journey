# TIL 초안 작성

## 원칙
- 채팅으로 초안만 제시한다. 파일 생성·저장·커밋은 절대 하지 않는다 (사용자가 직접 작성).
- 커밋 메시지를 먼저 제안하지 않는다. 사용자가 쓴 커밋 메시지를 보여주면 그때만 피드백한다.
- 이번 세션에서 실제로 한 작업과 확인된 사실만 쓴다. 추측한 내용은 "(확인 필요)"로 표시한다.
- 주제가 여러 개면 주제별로 초안을 나눠 제시한다.

## 파일명 제안
- 형식: YYYY-MM-DD_주제.md (영문 소문자, 단어 구분은 언더바)

## 초안 형식
~~~
## <주제 제목>

### 배운 것

**<소제목>**
- 핵심 개념은 짧은 불릿으로
- 폴더 트리, 명령어, 설정은 반드시 코드블록 안에

### 트러블슈팅
- 문제:
- 원인:
- 해결:
~~~
- 트러블슈팅이 없으면 섹션을 생략한다.

## 커밋 메시지 피드백 (요청 시에만)
- 컨벤션: feat / docs / refactor / chore / fix
- TIL 추가는 보통 docs:
- 짧게 판정: 맞으면 "OK", 틀리면 어디가 왜 틀렸는지 한 줄
